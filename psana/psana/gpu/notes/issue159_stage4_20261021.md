# Issue 159 stage 4: aligned public field views

Stage 4 is implemented; isolated CUDA validation and the short performance
screen are pending. Stage 5's direct host-byte copy optimization is separate.

`GpuFieldResult` checks the actual input pointer plus locator offset before
forming a typed view. Aligned fields keep the original pointer. Unaligned fields
use one byte-oriented device copy into an `owned_empty` allocation, preserving
shape (including scalars), dtype and exact object bits. Absent segments allocate
nothing. XTC input bytes and offsets are unchanged.

The existing event input lease owns a lazy cache keyed by detector, algorithm,
field and physical segment. Whole-field and single-segment requests share its
allocation and readiness event. The manager's finalized budget reaches this
lease through `EventPool`; no separate allowance or IPC allocation is introduced.
Actual pool capacity is charged once and aliases keep their charge.

A requesting stream first waits for producer readiness. Materialization records
a copy-ready event; later accesses wait on it, including another stream. Copies
are retained by the stage-3 root lease independently of public view caches.
Retirement clears access caches, while open children and registered completion
keep both source and copy alive. If copy submission or event recording fails,
the submitting stream becomes a completion token before a drain is attempted.
Failed drains retain ownership and can be retried. Failed materialization never
publishes a public result or a partially initialized copy-cache entry.

`on_gpu_view` means borrowed access: first unaligned access may copy. This caveat
is now in its docstring and `docs/gpu_xtc_parser.md`. `.on_gpu` continues returning
an independent copy; `.on_cpu` currently uses safe views. Avoid attributing
stage-5 direct-byte host-copy behavior to this stage.

Validation includes numeric widths 1/2/4/8, all address residues, independently
shifted bases, exact end bounds, scalars/empty arrays/ragged shapes, absent
segments, shared cache identity, budgets, allocation/submission/record/drain
failures, and event replacement. Real-device tests additionally use typed loads
under memcheck and delayed producer/copy/consumer streams across retirement.
