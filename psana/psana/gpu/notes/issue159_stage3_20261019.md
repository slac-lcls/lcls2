## Ownership

`InputSlotLease.retain_copy(array)` holds a field allocation independently of
`GpuFieldResult._views`. Call it before asynchronous work is submitted; register
completion on the submitting lease, or drain that stream if submission fails.
The later field implementation must also order consumers after copy readiness.

Children keep a reference to their root lease and share its lock. A child opened
before the first copy protects subsequent copies too. Parent retirement closes
public access and clears cached views, but cannot release retained allocations
while a child remains open. Child completion tokens are accumulated on the root;
the final drain waits for the relevant producer/consumer events before releasing
the retained references. Input owners continue to use their existing completion
and reuse machinery.

Failed completion leaves storage and its allocation charge retained for retry.
Repeated cleanup does not return a child twice. Nested children refer directly
to the root, so intermediate retirement cannot release storage early. Escaped
array aliases continue to retain their existing allocation-backed charge after
the lease releases its own reference.

With no copies requested, the new retention lists stay `None`. There are no
copy-specific device allocations, CUDA events, completion waits, or changes to
owner retirement. Existing field contexts gain root/child bookkeeping; event
leases gain a few scalar attributes. That Python cost is measured separately.

## Validation design

- CPU tests use allocation-backed NumPy fixtures and weak references to check
  exact charge/owner retention, both parent/child retirement orders, children
  opened before/after copies, nested children, deferred completion failure and
  retry, context-entry/body/record/drain failures, and the no-copy path.
- CUDA tests use real budgeted allocations, two delayed consumers on separate
  streams, parent cache retirement, and an early child. Assert actual pending
  CUDA work, retained storage and charge, final release, and exact output pixels.
  Existing input/group ownership, slot reuse and raw-preparation tests also run.
- Compute Sanitizer covers the new device lifetime cases in a separate process.
- The identical [host benchmark](../scripts/bench_input_lease.py) measures event
  construction and retirement with/without a child view in fresh A/B processes
  pinned to one CPU. It performs no I/O, GPU submission or field materialization;
  report microseconds/event without treating it as detector throughput.
- Eight staged 10k-event samples compare accepted stage 2 against stage 3 with
  two balanced pairs for warm/bulk-off and warm/bulk-on. Four 200-event pixel and
  address preflights precede timing. Preserve the earlier workload, 4BD/1GPU,
  batch 20, depth 1, CPU-fallback KvikIO, 6 GiB/BD, private staged prefix hashes,
  cache-residency, timestamp/read/budget/drain and runtime-provenance checks.
